## 사용자가 발급한 상담 웹 앱 연결

제공된 Apps Script `/exec` 주소를 폼의 기본 저장 주소로 연결했습니다. GitHub Pages에서 환경변수가 비어 있어도 연결이 유지되며 별도 주소로 재정의할 수 있습니다. 명시적으로 `disabled`를 지정하면 접수를 비활성화합니다.

Pages 빌드·타입 검사와 단위 테스트 10개, 운영 주소를 POST하지 않는 데스크톱/모바일 E2E 12개를 통과했습니다. 실제 폼 action·이름 입력·상담하기 활성 상태를 확인했고 제출 전에는 Google 웹 앱 요청이 발생하지 않음을 확인했습니다. 모의 서버·미설정 전용 테스트 10개는 해당 테스트 모드가 아니므로 의도적으로 건너뛰었습니다.

실행 환경은 Google 웹 앱에 프록시 403을 반환해 실제 테스트 접수는 보내지 못했습니다. 웹 조회 도구에서도 해당 주소를 열 수 없었습니다. 따라서 실제 Google Apps Script 권한·배포 버전·시트 저장·성공 응답은 아직 미검증이며 사용자 브라우저에서 테스트 신청 후 시트에서 확인해야 합니다. 접속 제한을 우회하지 않았고 실제 접수를 성공했다고 표시하거나 기록하지 않았습니다.

## 실제 접수 실패 재현: 동의문 줄바꿈

사용자 브라우저에서 서버 오류 응답이 돌아왔고 상담 시트에는 기록이 없었습니다. 네이티브 HTML POST를 Chromium에서 재현한 결과, 동의문 숨김 필드의 LF가 CRLF로 변환되어 원본 문자열과 정확 일치하지 않음을 확인했습니다. 기존 모의 서버 테스트가 실제 폼 직렬화까지 검증하지 못해 이 차이를 놓쳤습니다.

Apps Script 수신부에서 두 동의문의 CRLF/CR만 LF로 정규화한 뒤 비교하도록 수정했습니다. 의미 있는 문구 변경·동의문 버전·선택 동의 검증은 유지합니다. 단위 테스트 11개, Pages 빌드·타입 검사, 실제 폼 전송 줄바꿈 검증을 포함한 모의 서버 브라우저 테스트 8개가 통과했습니다. 목적이 다른 미설정/실제 운영 주소 테스트 4개는 해당 모드에서 건너뛰었습니다.

실제 Apps Script는 사용자의 계정에 배포되어 있어 GitHub 수정만으로 갱신되지 않습니다. 사용자가 최신 Code.gs를 저장하고 기존 배포를 새 버전으로 갱신한 뒤 실제 시트 저장을 다시 확인해야 합니다. 실제 고객 접수 성공을 아직 주장하지 않습니다.
