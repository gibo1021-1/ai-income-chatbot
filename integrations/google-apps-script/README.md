# 전화 상담 저장 연결 — Google Apps Script

웹사이트는 GitHub Pages를 유지합니다. 개인정보는 비공개 구글시트에만 저장하며 API 키를 브라우저에 넣지 않습니다. 이 연결을 배포하기 전에는 전화 상담 입력·전송을 비활성화합니다. 수집 주체와 보유기간은 운영자가 확정해야 합니다.

## 구글 계정에서 한 번만 설정

1. 준비된 **비공개 상담 관리 구글시트**를 엽니다. 시트를 웹에 게시하거나 링크가 있는 모든 사용자에게 공유하지 마세요.
2. 상단 **확장 프로그램 → Apps Script**를 엽니다.
3. `Code.gs` 파일에 이 폴더의 `Code.gs` 전체를 붙여넣고 저장합니다.
4. 함수 목록에서 **setup**을 선택해 한 번 실행하고 필요한 스프레드시트 권한을 승인합니다. 이 시트를 자동으로 연결하며 기존 데이터와 헤더는 덮어쓰지 않습니다.
5. 수집 주체 **북 브랜딩 랩**, 보유기간 **수집일로부터 3년**이 코드 기본값으로 반영되어 있습니다. 별도 속성 입력은 필요하지 않습니다. 다른 시트 또는 정책을 사용해야 할 때만 프로젝트 설정 → 스크립트 속성에서 `SPREADSHEET_ID`, `PRIVACY_CONTROLLER`, `PRIVACY_RETENTION`을 변경하세요.
6. **배포 → 새 배포 → 유형: 웹 앱**을 선택합니다.
7. 실행 사용자: **나**, 액세스 권한: **모든 사용자(로그인 없이)**로 선택하고 배포합니다. 코드에는 시트 읽기/다운로드 API가 없고 유효한 동의가 있는 접수만 추가합니다. 조직 정책이 익명 웹 앱을 금지하면 다른 저장 서버가 필요합니다.
8. 발급된 `https://script.google.com/macros/s/…/exec` 주소를 전달합니다. 개발용 `/dev` 주소는 사용할 수 없습니다.
9. GitHub 저장소 Settings → Secrets and variables → Actions → Variables에 아래 세 값을 설정하고 **Deploy GitHub Pages**를 다시 실행합니다.

| 변수                                | 값                                           |
| ----------------------------------- | -------------------------------------------- |
| `NEXT_PUBLIC_CONSULTATION_ENDPOINT` | 위 `/exec` 주소                              |
| `NEXT_PUBLIC_PRIVACY_CONTROLLER`    | 스크립트 속성과 정확히 같은 주체명           |
| `NEXT_PUBLIC_PRIVACY_RETENTION`     | 수집일로부터 3년（스크립트 속성과 동일하게） |

기본 주체·보유기간은 양쪽 코드에 동일하게 반영되어 있으므로 웹 앱 주소만 연결해도 됩니다. 주체·보유기간·동의문 버전이 양쪽에서 다르면 서버가 접수를 거부합니다. 동의문을 수정할 때는 클라이언트와 서버의 버전을 함께 변경하고 웹 앱을 새 버전으로 배포해야 합니다.

## 실제 접수 확인 — 연결 후 필수

1. 시크릿 창에서 진단 완료 → 테스트 이름·테스트용 연락처 → 동의 체크 → 상담하기.
2. 화면에 **접수 완료**가 나오고 비공개 시트에 접수번호가 같은 행이 한 개 생성되는지 확인합니다. 실제 고객 정보로 테스트하지 마세요.
3. 전화번호의 앞자리 0, 진단유형·추천과정, 동의문·버전을 확인합니다.
4. 동일 정보로 재시도해도 같은 접수번호는 한 번만 저장되는지 확인합니다.
5. 동의하지 않으면 전송되지 않는지, 서버 오류·시간 초과 때 접수 완료로 표시하지 않는지 확인합니다.
6. 확인용 테스트 행을 삭제합니다.

**Apps Script 실제 배포와 위 시트 쓰기 확인 전에는 접수 기능이 운영 완료된 것이 아닙니다.**

## 담당자의 상담 관리

`상담신청` 탭에서 신규 신청을 확인하고 전화를 건 뒤 `상담상태`와 `상담 메모`를 기록하세요. 파일 → 다운로드 → Microsoft Excel(.xlsx)로 엑셀 파일을 받을 수 있습니다. 필요한 담당자만 시트를 공유하고 확정한 보유기간이 지나면 해당 행과 별도 다운로드 사본을 삭제하세요. 현재 자동 파기·전화 발신·담당자 알림은 포함하지 않습니다.

## 전송·운영 특성

- POST로 전송하며 URL에 이름·전화번호를 붙이지 않습니다. 브라우저 저장소·분석 도구·GitHub에는 저장하지 않습니다.
- Apps Script가 시트 저장을 완료한 뒤 해당 요청 ID와 함께 성공 신호를 보냅니다. 단순 iframe 로딩이나 불투명 응답을 성공으로 간주하지 않습니다.
- 오류나 30초 확인 지연은 재시도를 안내합니다. 같은 이름·번호·유형의 재시도는 동일한 요청 ID를 사용하고 서버가 중복을 차단합니다. 새로고침 후에는 ID가 바뀌므로 담당자가 중복 연락처를 확인해야 합니다.
- 서버는 동의·이름·연락처·유형·스키마를 검증하고 동시 저장 잠금, 허니팟, 연락처별 60초 및 분당 30건 제한을 적용합니다. 공개 접수 URL이므로 외부 스팸 가능성과 Google 실행 할당량은 운영 중 확인하세요.
- 보유기간에 맞춘 파기는 운영자 책임의 수동 절차입니다. 자동 파기 구현이 필요하면 실제 보유 기준(접수일/상담완료일 등)을 확정해야 합니다.

## 확정한 개인정보 안내

- 수집·이용 주체: 북 브랜딩 랩 (직접 수집하는 운영자, 위탁받는 자로 표시하지 않음)
- 보유·이용 기간: 수집일로부터 3년
- 필수 목적: 코칭 및 교육을 위한 참고자료 활용, 진단 결과에 따른 전화 상담 및 과정 안내
- 필수 항목: 이름·연락처·진단유형·추천과정
- 별도 선택 목적: 이메일 뉴스레터 발송
- 선택 항목: 이름·이메일. 선택 동의하지 않은 이메일은 전송·저장하지 않습니다.
- 뉴스레터 동의 없이도 전화 상담 신청이 가능합니다. 선택 동의 시에만 이메일 주소 입력을 요구합니다.
- 동의문 버전: 2026-11-02-v2. 클라이언트와 Apps Script의 동의문이 일치해야 저장합니다.
- 이메일 자동 발송은 포함되지 않습니다. 시트에 저장된 수신 동의 목록을 기준으로 운영자가 발송합니다.

## 접수 오류 수정: 동의문 줄바꿈

브라우저의 폼은 동의문 줄바꿈을 LF에서 CRLF로 바꿔 전송합니다. 같은 내용이 거부되던 문제를 수정했습니다. 최신 `Code.gs` 전체를 붙여넣고 저장한 뒤 **배포 관리 → 수정 → 새 버전 → 배포**로 반영해야 합니다. 줄바꿈만 정규화하며 문구와 동의문 버전의 일치 검증은 유지합니다.
